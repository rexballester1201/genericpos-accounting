1The stack, and where things live

2A request, end to end

  1. .htaccess sends everything that is not a real file to index.php, and refuses application/, docs/, tests/, SCHEMA.sql and every .md, .sql, .log and .env outright.
  2. index.php decides the environment. Development needs both the Host header and a request from this machine, so a forged header on a public server cannot turn error pages on. It then loads application/core/Api_errors.php, which installs the handlers that make an uncaught exception or a fatal answer in the JSON envelope on any /api/ path.
  3. CodeIgniter routes the URI. config/routes.php holds the shared routes and then includes config/routes/{receivables,banking,assets,budgets,ledger,admin_tools}.php. A module file that fails to parse is logged and skipped rather than taking every other route down with it.
  4. The controller method's first statement is its guard — viewer_check(), bookkeeper_check(), accountant_check() or admin_check(). Each verifies the token, re-reads the account and its role from the database, and returns the claims, or exits with 401 or 403. There is no middleware to forget to register; the guard is in the method.
  5. The model does the work inside a transaction and returns either a result or a message.
  6. json_response() or json_error() writes the envelope and exits.

3The API

170 routes under /api/v1. Every answer is the same shape:

{ "status": true,  "data": { … },  "message": "Saved" }
{ "status": false, "data": null,   "message": "That month is closed.",
  "errors": { "entry_date": "That month is closed." } }
ConcernHow
AuthenticationHS256 JWT in Authorization: Bearer. Claims: user_id, role, account_state, auth_method, plus iss, iat, exp, jti. Twelve hours.
RefreshOpaque token in gp_refresh_tokens, thirty days, spent once. A reuse revokes the whole family and logs auth.refresh_reuse; a 60-second grace covers two tabs refreshing together.
Status codes200 fine · 401 no or bad session · 403 wrong role · 404 missing · 405 wrong method · 409 conflict · 422 validation, with errors keyed by field · 429 rate-limited · 500 fault (still JSON).
Paginationpage and per_page in, { items, meta: { page, per_page, total, pages } } out.
Rate limitingPer user and action in gp_rate_limits, on every write and on sign-in.
CSVAny report takes format=csv and answers a UTF-8 file with a byte-order mark and the letterhead in its first rows.
Auditlog_admin_action() writes one immutable row per staff mutation, inside the same transaction as the change. Work nobody signed in for — the command line, the scheduled job — is recorded against the system actor and shows as "System".

4The ledger engine

application/models/Journal_model.php is the only code that writes journal lines. Four ways in, and nothing else:

CallUsed byWhat it does
post_system($head, $lines, $uid, $source, $source_id)Every moduleValidates, numbers, posts and audits in one transaction. The source and its id tie the entry to the document that caused it.
reverse_system($id, $uid, $date, $reason, $source)Every moduleReverses an entry that module posted. Refuses a manual entry, refuses a reversal, and checks the source matches.
create_draft($head, $lines, $uid, $source, $source_id, $actor, $note)Recurring entriesA draft for somebody to approve. The actor is who made it — the scheduled job records itself, not the owner.
the workflow methodsScreensupdate_draft, submit, approve, reject, cancel, reverse — the manual path, each with its own rules.

What is checked before anything is written

  • Two or more lines; debits equal credits; every line has exactly one side.
  • The date falls in an open period of an open year.
  • Every account exists, is active and is postable — never a header.
  • A line on a control account names an active customer or supplier; a line on an account that requires a department names one.
  • The book is one of general, cash_receipts, cash_disbursements, sales, purchases, adjusting, closing, opening. The last two are system-only.

Posting re-runs the whole validation against the stored lines inside the posting transaction, not against what was submitted, so a chart change between submission and approval cannot slip a bad line through. An account's control and needs-a-department flags freeze once it has any line at all.

Numbering

next_sequence() takes a row lock on gp_counters and hands out the next number for that book and fiscal year. The number is assigned at posting, inside the transaction, so a rolled-back posting consumes nothing and a book's numbers have no gaps. Prefixes come from Settings, which refuses a blank or duplicated one.

Nested transactions throw

CodeIgniter 3 counts transaction depth, and only the outermost commit or rollback reaches the database — an inner rollback does nothing. So when post_system() is called inside a caller's transaction and something fails, it throws rather than returning an error, and the caller must let the exception roll its own transaction back. Note that mysqli_sql_exception extends RuntimeException: catch the SQL exception first, or a database fault is mistaken for a rule violation.

gp_ledger

A view over gp_journal_lines joined to gp_journals, giving every line its entry's book, number, date, period, fiscal year, source and description, plus net_cents = debit_cents - credit_cents. Every report reads the view; nothing writes to it.

Rules the database itself enforces

  • A line has a debit or a credit, never both and never neither (CHECK).
  • An allocation is positive and cannot exceed its settlement (CHECK).
  • Account codes, journal numbers per book and year, and document numbers are unique.
  • Strict mode is on, so a value that does not fit is refused rather than silently truncated.

7Reporting

Statement_lib
The four statements, laid out from the chart: type chooses the statement, subtype the section, the header tree the line items. Each returns { title, columns, lines, base, checks, totals }, where a line is typed — section, heading, header, account, group, subtotal, total, computed, grand — and the browser only draws. Cash flows come both ways: the indirect method from net income and the movements, the direct method read outward from the cash accounts, with the indirect operating section carried underneath as the reconciliation note.
Books_lib
The five books of accounts, entry by entry or columnar and paged, with page totals and the amount brought forward.
Analysis_lib
Twenty-one ratios with their formulas and inputs, and the co-operative indicators against benchmarks held in Settings.
Integrity_lib
Sixteen ties over the stored records: the ledger against itself, the subsidiary ledgers against their control accounts, documents against their entries, the asset register against accumulated depreciation, the counters against the numbers actually used.
report_helper
The letterhead, the CSV download and amount_in_words(), shared by every report so they all print the same.

8The front end

One shell, one router, one module per screen. No framework and no build step: the browser loads ES modules straight from disk.

// js/<page>.js — every screen looks like this
export async function mount(root, ctx) { … }

// ctx: { route, params, query (URLSearchParams), user, signal,
//        navigate, setTitle, refreshChrome }

pages/<page>.html carries the markup and names its module in data-module. The router matches the path, checks the role, fetches the page, imports the module and calls mount. ctx.signal aborts when the user navigates away, so a slow request cannot paint over the next screen.

Shared moduleWhat it gives
api.jsapi.get/post/put/del/upload, the session, refresh-on-401, download(). An ApiError carries status and errors.
ui.jsEscaping, form values and errors, busy states, toasts, dialogs, status pills.
store.jsThe company's settings, money in and out of centavos, date formatting.
report-kit.jsAmounts and percentages, the sheet head and foot, period presets, links into the general ledger, the address bar, CSV export.
icons.jsInline SVG, painted on demand. Every icon a page names must exist.

After any front-end change

Raise CACHE_VERSION in sw.js, and add any new js/ or pages/ file to its precache list. A browser that already has the old worker will otherwise keep serving the old app. node tests/modcheck.mjs checks that every import resolves, every route has a page, every page has its module and every icon used is defined.

9What the security rests on

  • Tokens. HS256, signed with GP_JWT_SECRET, which has no fallback — a missing secret is a clean 503, never a known default. alg: none is rejected loudly. Every token carries an issuer claim that validation checks, so a token minted by another application on the same machine is refused even if the two ever shared a secret.
  • Roles are re-read from the database on every request. A suspended account stops working immediately, not at the next sign-in.
  • Refresh tokens rotate and are spent once; a replayed one ends every session of that account.
  • Changing the email address on an account takes the current password, feeds the lockout counter, is audited, and notifies the old address with the new one masked.
  • Every write is rate-limited per user and audited in the same transaction. A failed audit row fails the change.
  • Attachments are never served by the web server: a deny-all rule in uploads/attachments/, the type sniffed rather than trusted, and a guarded endpoint that streams them with nosniff and a sandbox.
  • Development mode needs the Host header and a request from the machine itself, so a public server cannot be talked into showing file paths.
  • SQL goes through bound parameters; search terms have their wildcards escaped.

10The tests

Sixteen suites, 677 checks. They talk to the API the way the browser does, against a throwaway database served by PHP's own web server; several refuse outright to run against a database whose name does not say "scratch", so a real set of books cannot be touched.

mysql -u root -e "CREATE DATABASE acc_scratch CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
mysql -u root acc_scratch < SCHEMA.sql
CI_ENV=development GP_DB_NAME=acc_scratch php index.php tools seed_demo
GP_DB_NAME=acc_scratch php -S 127.0.0.1:8781 -t . tests/router.php   # leave CI_ENV unset here

node tests/api-test.mjs     http://127.0.0.1:8781/api/v1 ledger
node tests/reports-test.mjs http://127.0.0.1:8781/api/v1
node tests/modcheck.mjs

The suites mutate the seeded books, so re-seed between the ones that close a year or register an asset. tests/README.md lists them all and what each covers. Afterwards, drop the scratch database and run php index.php tools cache against the real one — seeding rewrites the sign-in page's branding cache.

11Conventions, and the traps

  • Money is integer centavos everywhere, named *_cents. Rates are basis points. Dates are Y-m-d strings. Use company_today(), not date() — the company's timezone is a setting.
  • The guard is the first line of every controller method. A method without one is a bug, not a public endpoint.
  • Never write journal lines directly. If a new module needs to post, it calls post_system() and defines a new source.
  • Catch mysqli_sql_exception before RuntimeException, since the first extends the second.
  • An account's flags freeze once it has a line. Design the chart before the first entry, or expect to be refused.
  • Settings that were chosen at setup — the kind of organisation, the business form, the fiscal-year start month — are read-only afterwards, by design.
  • Strict SQL mode is on. A query that used to pass a slightly wrong value now fails. That is the point.
